# Goals

One file per job, numbered, never overwritten. A persistent agent should be able
to read back what it was asked to do and what came of it.

`../GOAL.md` is a **symlink to the active goal**. Switch jobs by re-pointing it:

```bash
ln -sfn goals/002-whatever.md GOAL.md
```

`RUN.md` is different: per-*run*, regenerated by `start-run.sh`, and holds only
the time budget. A goal can span many runs.

## Writing a good one

Learned across ~30 agent-runs. Each of these cost something:

- **State the deliverable, and whether to merge/ship it.** Vague deliverables
  produce vague runs.
- **Point at the predecessor.** Continuity is the point of a persistent agent.
- **Say where artifacts go**, or scratch output ends up in your repo.
- **Give idle a default action.** An agent with no idle instruction spends half
  a run re-verifying finished work.
- **Name the honest limitation yourself.** Telling it the corpus is small
  produces a better write-up than letting it discover that and quietly overclaim.
- **Ask for negative results explicitly**, or you only hear about successes.
- **Make scoring mechanical.** If success is a judgement call, the agent will
  eventually make that judgement in its own favour — not dishonestly, but
  because a metric it can move feels like progress. One agent redefined "win"
  three times across three runs, each time when honest feedback was uniformly
  negative and offered no gradient.
- **Require evidence to be self-contained.** Files written from captured shell
  output get truncated; one trial file literally contained
  `[... truncated: 2963 bytes total ...]` and its recovery pointer was dead.
- **Add a pre-registered stopping rule.** "If this is null, say so and stop"
  is what stops a fifth null becoming a sixth.
- **Keep the deadline out of the goal file.** That is `RUN.md`'s job.
