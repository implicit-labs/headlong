# Goals

One file per job, numbered, dated, never overwritten. A persistent agent should
be able to read back what it was asked to do and what came of it.

`../GOAL.md` is a **symlink to the active goal**. Switch jobs by re-pointing it:

```bash
ln -sfn goals/002-whatever.md GOAL.md
```

`RUN.md` is different: per-*run*, regenerated by `start-run.sh`, holding only the
time budget. A goal spans many runs. Keep deadlines out of goal files.

Start from [GOAL-TEMPLATE.md](GOAL-TEMPLATE.md).

| # | Goal | Created | Completed | Status | Outcome |
|---|------|---------|-----------|--------|---------|
| 001 | | | — | **active** | — |

Fill the outcome column when a goal closes, in one sentence, including when the
answer was "no". The table is the fastest way for the next run — or the next
person — to avoid redoing work.

## The deliverable is the part that fails

Everything below is secondary to this.

A goal that specifies a **schema** gets a schema. One agent produced entries
that filled every required field and were hollow; the spec could not catch it,
and a stricter spec would not have either. What was missing was a plain-language
statement of what a good unit *is* — *"a quote is a sentence that makes a
point"* — said out loud.

So every goal opens with **THE DELIVERABLE**, and it does three things:

1. **Says it is the main goal**, and that the rest of the file is detail
   underneath it. Agents optimize what is emphasized.
2. **States that schema compliance is not doneness.**
3. **Gives every field a test whose failure is observable.** Not "is this
   insightful" — *"if sentence 3 could be written about any article, it fails."*

Then: a unit ships only if it passes all of them.

## What else demonstrably matters

Each of these cost a run to learn:

- **Point at the predecessor.** Continuity is the point of a persistent agent.
  Say "read it, do not re-execute it."
- **Say where artifacts go**, or scratch output becomes commits.
- **Give idle a default action.** With none, an agent spends half a run
  re-verifying finished work.
- **Make scoring mechanical.** If success is a judgement call, the agent will
  eventually make that call in its own favour — not dishonestly, but because a
  metric that moves feels like progress. One agent redefined "win" three times
  across three runs, each time when honest feedback was uniformly negative.
- **Require evidence to be self-contained.** Files written from captured shell
  output truncate; one trial file literally contained
  `[... truncated: 2963 bytes total ...]`.
- **Name the honest limitation yourself.** Telling an agent the corpus is small
  produces a better write-up than letting it discover that and quietly overclaim.
- **Ask for negative results explicitly**, or you only hear about successes.
- **Add a pre-registered stopping rule.** "If this is null, say so and stop" is
  what stops a fifth null becoming a sixth.
- **Warn about metric drift in the goal itself.** The line that works: *if your
  success rate jumps, ask what changed about the test.*

## Sizing a run

- Under an hour is a trial. Say so, and name the one slice worth finishing.
- Volume work (many trials, many files) suits `claude-sonnet-5`.
- Design and taste work suits `claude-opus-5`. Set it in `info.txt`
  (`think_model=`) and the identity `.env` (`SHELLM_MODEL=`).
- A long run needs an idle default and a stopping rule more than a short one.
