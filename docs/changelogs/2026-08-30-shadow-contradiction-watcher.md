# Saturation guardrails and shadow Contradiction Watcher

**2026-08-30** · branch `feat/headlong-shadow-watcher`

An unattended Treasurer run had completed its goal but kept waking, repeating
the same prior-art thought, and spending. Its read-only boundary was also prose
plus a permissive network sandbox: a nested investigation downloaded source to
`/tmp`, and an obvious `test` probe reached the live Sentience API.

This change turns those incidents into enforcement:

- long-run workspaces saturate after three empty or identical spontaneous
  wakes, remove their timer, and resume only for a real external event;
- nested shellm results and parent/child manifests persist privately under the
  workspace artifact directory instead of disappearing into `/tmp`;
- live-question wrappers can reject empty, option-only, and filler probes before
  ledger increment or network;
- workspace curl is denied by default and, when explicitly enabled, permits
  only GET/HEAD to exact operator allowlisted hosts;
- `headlong-contradiction-watcher` reads tagged memory and records private,
  deduplicated shadow candidates for human review. It has no delivery code and
  installs no timer.

The first authorized live-memory baseline read 25 Treasurer memory files: seven
had explicit/legacy-explicit watcher types (four beliefs, three actions/goals),
and zero candidates passed. An initial generic-word subject match was retained
in the immutable screened ledger, then eliminated by tightening the subject
gate; the calibrated rerun produced zero candidates and zero screened conflicts.

Verification: 41 focused assertions pass across saturation, question/network
guards, sub-run persistence, and the watcher. The repository-wide runner passed
38 suites; four unrelated checks depend on operations blocked by the enclosing
Codex sandbox (local-clone hardlinks, process-table visibility, and feeder
process visibility).
